# Test Gaps

実装が終わった差分について、「どこまで安心してよいか」の境界を先に言い切り、境界の外側を処置つきで提示する。手動テストの一覧を作るのではなく、リリース判定に必要な判断材料を作る。

## 守ること

- 境界を先に出す。読み手は一覧より先に「自動テストが何を証明したか」を知りたい
- 穴ごとに処置を言い切る。ユーザーは推奨との差分だけ直せばよい形にする
- 人が動く項目は多くても 5 個。少なければ少ないまま出し、埋めない。残りはテストに回すか、理由 1 行で「確認不要」に畳む
- 合否基準は見たら OK/NG が決まる形にする（「悪化していない」ではなく「変更前の p95 の 1.5 倍以内」）。基準が書けない項目は確認内容が定まっていないので、そこで止まってユーザーに聞く
- fixture や golden を足せば自動化できるものはテストに回す。手動に残すのは、外部システム・本番規模のデータ・人の目が要るものだけ
- この差分が新たに生んだリスクと、もともとあった穴を分ける。混ぜると PR の影響が実際より大きく見える
- 出力を読む外部システム（クローラ、連携先、Webhook の受け手）はコードから見えない。GLOSSARY・ADR・docs・チケットで探し、見つからなければ「この出力を読む外部システムはあるか」をユーザーに聞いてから処置を決める

## 手順

### 1. 境界を言い切る

差分と、それを固定している自動テスト（unit / handler / golden / fixture）を読み、そのテストを実行して通ることを確かめる。golden が xlsx などのバイナリなら展開（unzip）して、変更前（HEAD）と何が変わったかをセル単位で見る。完了基準: 変更した挙動ごとに、それを固定しているテストと、そのテストが通った事実を挙げられる。挙げられない挙動が穴の候補になる。

出力は 1〜2 行。「golden で値・並び・空セルは固定した。固定していないのは A・B・C」の形。

### 2. 穴を洗い出す

差分の種類に応じて次の観点をなめる。該当しない観点は飛ばす。

- 外部システム: このリポジトリの外で差分の出力を読む相手（連携先、クローラ、Webhook の受け手）
- 本番規模: 件数に比例してコストが増える箇所、同期処理の上限、index が効くか
- 人の目: ファイルの体裁、画面の表示、複数のクライアント（Excel / スプレッドシート / ブラウザ）での見え方
- 一連の操作: フロントエンドから API までを通した流れ
- データ変化後: マスタの改名・削除、スナップショット後の更新、再 index 前後
- リリース手順: migration、再 index、設定変更、バッチの再実行
- 権限・マスキング: 触っていなければ「確認不要」に畳む

### 3. 処置を割り当てる

各穴を次の 4 つのどれかに置く。

| 処置 | 置く条件 | 書くこと |
|---|---|---|
| テストを足す | fixture・golden・mock を足せば自動化できる | 足すテストの観点 |
| 人が動く | 外部システム・本番規模・人の目が要る | いつ・誰が（マージ前に開発者 / stg で QA / リリース前に外部へ依頼）、合否基準、リリース判定の条件かどうか |
| もともとの穴 | 差分の前から存在し、差分は影響を少し変えただけ | 1 行。この PR の論点ではないと明記 |
| 確認不要 | 触っていない、または構造上起きない | 理由 1 行 |

### 4. 出す

最終メッセージはこのテンプレートだけにする。調査のメモ（読んだファイル、実行したコマンド）はテンプレートの前に置かず、必要なら表の理由欄に畳む。PR テンプレートのテスト欄と QA のチケットにそのまま貼れる文面にする。

セルは 1 文で書く。観点は手順 2 の名前（外部システム / 本番規模 / 人の目 / 一連の操作 / データ変化後 / リリース手順 / 権限・マスキング）をそのまま使い、読み手が観点名で拾えるようにする。

```
## 自動テストで固定した範囲
<1〜2 行。固定した挙動と、固定していないものの名前>

## 人が動く項目
| # | 観点 | 項目 | いつ・誰が | 合否基準 | リリース判定 |
|---|---|---|---|---|---|
| 1 | 外部システム | … | リリース前に PdM 経由で stg | … | 条件 |
| 2 | 人の目 | … | マージ前に開発者がローカル | … | — |

## その他の穴
| 処置 | 観点 | 項目 | 理由 |
|---|---|---|---|
| テストを足す | … | … | 足すと固定できる観点 |
| もともとの穴 | … | … | 差分の前から同じ。この PR の論点ではない |
| 確認不要 | … | … | 触っていない／構造上起きない |
```

「人が動く項目」が 0 件なら表を出さず「なし」と書く。「その他の穴」は処置ごとに行をまとめ、同じ処置が複数あれば行を増やす。

「テストを足す」はユーザーの承認を待ってから実装する。承認されたら、テストケース数はプロジェクトのテストガイドラインに従う。
